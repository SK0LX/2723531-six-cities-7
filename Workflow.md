# Как работать над проектом

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS релиз Node.js**. Актуальная версия **Node.js** указана в файле `package.json` в поле `node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Для актуальных версий `got` и JSON-server требуется Node.js 22.12.0 или новее.

Команда запустит процесс установки зависимостей проекта из **npm**.

### Сценарии

В `package.json` предопределено несколько сценариев.

#### Скомпилировать проект

```bash
npm run compile
```

Создаст директорию `dist` и скомпилирует проект.

#### Удалить скомпилированный проект

```bash
npm run clean
```

Удаляет директорию `dist`. Используется перед компиляцией.

#### Собрать проект

```bash
npm run build
```

Выполняет сборку проекта: удаляет ранее скомпилированный проект и компилирует заново.

#### Проверить линтером

```bash
npm run lint
```

Запуск проверки проекта статическим анализатором кода **ESLint**.

Линтер проверяет файлы только внутри директории `src`.

**Обратите внимание**, при запуске данной команды, ошибки выводятся в терминал.

#### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

#### Запустить проект

```bash
npm start
```

В процессе запуска проекта будет выполнен процесс «Сборки проекта» и запуска результирующего кода.

#### Запустить сервер тестовых данных

```bash
npm run mock:server
```

Запускает JSON-server с данными из `mocks/mock-server-data.json` на порту `3123`.
Заготовки для генерации предложений доступны по адресу `http://localhost:3123/api`.

Сервер работает, пока открыт процесс в терминале. Для остановки нажмите `Ctrl+C`.

#### Сгенерировать тестовые предложения

Сначала запустите сервер тестовых данных. В другом терминале, из корня проекта, выполните:

```bash
npm run cli -- --generate 100 ./mocks/generated.tsv http://localhost:3123/api
```

Команда получает заготовки с сервера и записывает 100 предложений в TSV через поток.
Количество предложений должно быть положительным целым числом. Директория для файла должна существовать.
При повторном запуске файл перезаписывается.

Сгенерированные TSV-файлы исключены из Git. Исключение — учебный файл `mocks/test.tsv`,
который содержит два предложения, созданных вручную.

#### Импортировать предложения

Запустите MongoDB из корня проекта:

```bash
docker compose -f docker-compose.dev.yml up -d db
```

Передайте путь к TSV, URI базы данных и соль для хеширования паролей:

```bash
npm run cli -- --import ./mocks/test.tsv 'mongodb://<DB_USER>:<DB_PASSWORD>@127.0.0.1:27017/<DB_NAME>?authSource=admin' '<SALT>'
```

Замените значения в угловых скобках настройками своего окружения. Соль должна совпадать
со значением `SALT` в `.env`, а логин и пароль — с настройками MongoDB в Docker Compose.
Специальные символы в логине и пароле URI должны быть закодированы для URL.

Команда читает TSV через поток и сохраняет данные в коллекции `users` и `offers`.
Автор ищется по email: если он уже существует, используется найденный пользователь;
иначе создаётся новый с хешированным паролем. Предложение хранит ссылку на автора.
Количество комментариев нового предложения равно нулю.
Повторный импорт создаёт новые предложения, а пользователей с теми же email использует повторно.
После успешного импорта выводится количество сохранённых предложений. Соединение с базой
закрывается после завершения чтения, в том числе при ошибке обработки строки.

Файл не загружается целиком в память. Поддерживаются файлы больше 2 GB,
переносы строк LF и CRLF, а также последняя строка без переноса.
Пустые строки пропускаются. При ошибке разбор останавливается и выводится её описание;
для ошибки в данных указывается номер строки. Уже сохранённые документы остаются в базе.

Чтобы проверить большой файл, сгенерируйте его при работающем JSON-server:

```bash
npm run cli -- --generate 4000000 ./mocks/generated.tsv http://localhost:3123/api
npm run cli -- --import ./mocks/generated.tsv 'mongodb://<DB_USER>:<DB_PASSWORD>@127.0.0.1:27017/<DB_NAME>?authSource=admin' '<SALT>'
```

Четыре миллиона предложений из текущих заготовок занимают больше 2 GB.
Импорт такого файла создаст четыре миллиона предложений в MongoDB и потребует
соответствующего места на диске и времени на запись.

## Структура проекта

### Директория `src`

Исходный код проекта: компоненты, модули и так далее. Структура директории `src` может быть произвольной.

### Файл `Readme.md`

Инструкции по работе с учебным репозиторием.

### Файл `Contributing.md`

Советы и инструкции по внесению изменений в учебный репозиторий.

### Остальное

Все остальные файлы в проекте являются служебными. Пожалуйста, не удаляйте и не изменяйте их самовольно. Только если того требует задание или наставник.
